## What it is

The tier rule (`candidate_line/tiers.py`) gives every turn a tier: 1 handled alone, 2 a person now, 3 written up after the call. Hand-offs go through the escalation queue (DR-013). The kill switch closes every call.

## The decision

- **The rule** is a pure function over the tools that did what was asked, the guard's hits, whether the refusal line was said, and the miss this turn added. Tier 2 when `move_slot` or `request_callback` ran. Otherwise tier 3 for a guard hit, the refusal (flagged by the loop or found in the spoken words), or a second failed verification. Otherwise tier 1. A hand-off outranks a write-up, and the write-up still reaches the call's end.
- **Tier 2 posts at once**, from the turn, with the masked caller and the cockpit trace link; the same reason twice on one call posts once. There is no hold this week: nobody staffs the cockpit, so a hold would always end at the limit. The caller hears that the coordinator calls back within one business day (spec 7.2), from the tool's own result.
- **Tier 3:** the reasons gather over the call, and `LineHooks.on_call_end` posts one hand-off after it, the reasons deduplicated, "read the trace" as the action.
- **The kill switch** is a file, `var/kill`, read at every turn's start and at every quiet stretch, and never cached. While it exists, a call closes with the closing line on the caller's first words or first quiet stretch, with no model call, and hangs up; the greeting is still said first. A `kill` span marks it; `rm` reopens the line. The tests point it at `tmp_path`.
- The cockpit's list shows each call's tier.

## Added 2026-11-04 evening: the caps and the channel

A cap is a control the public number needs before it is on any page. Without one, a dialler left running, or one caller who never hangs up, spends on Transcribe, Polly, the model and Twilio with nobody watching. Both caps are settings with a default, refused at start when they read as zero or as nonsense, so a typo can never switch one off without a word.

- **The length cap.** `MAX_CALL_SECONDS`, default 300. Once a call has run that long, Gus says "We're at the five-minute mark, so I'll let you go. Call back any time. Goodbye." and the call ends when its marks come back, the same way the hold-limit line ends a call. Any other value says "the time limit" in place of "the five-minute mark", so the line never states a length the setting does not hold. It fires only between turns: when a turn ends, after its reply has gone out in full, and in the silence watcher when Gus is quiet, no turn is being made and the caller is not mid-sentence. So it never cuts Gus or the caller off. Once the length line is queued, the caller's words neither clear it nor become a turn: a clear would empty Twilio's buffer, and the hang-up would then drop the caller mid-sentence with no goodbye heard (the review of the same evening, `tests/test_media.py`). A reply the caller cut into is left to the silence watcher, which waits for them to finish. It writes a `hook/length-cap` span with the call's seconds; not a `kill` span, because the line is still open and only this call has run its length (`candidate_line/telephony/media.py`, `candidate_line/persona.py`). Five minutes is two more than the three spec section 8 gives a good call.
- **The daily call cap.** `MAX_CALLS_PER_DAY`, default 30. The ledger counts the voice calls started each Central-time day, in the same `var/state.json` as the bookings, so a restart does not reset it (`Ledger.count_call`, `Ledger.calls_today`). The count is taken at `/voice`, after Twilio's signature check, so a forged request is refused before it is counted and a flood of them cannot close the line to a candidate. Past the cap the webhook answers with Twilio's own voice and no stream: "This is the ACME candidate line. The line is closed for the moment. Please try again later." The call row is started as any other and closed with the outcome "closed: daily cap" (`candidate_line/telephony/app.py`). A count that cannot be saved lets the call through and is logged: the cap bounds the bill, and a fault in the state file should not close the line.
- **The stream token.** Twilio does not sign the media stream's WebSocket handshake, and its Stream URL takes no query string; a `<Parameter>` arrives in the start message's `customParameters` (the Stream TwiML and WebSocket messages pages, read 2026-11-04). So `/voice`, after the signature check and the daily count, puts a token in the TwiML as a parameter, and `/media` opens a stream only with a live token minted for that call: its expiry, 60 s on, and an HMAC-SHA256 over the call SID and the expiry, keyed by the auth token. Each token opens one stream in the process. Without it, a client that learned the wss address could open `/media` with a made-up start message and spend on Transcribe, Polly and the model, counted against no cap and checked by no signature. A refused stream is closed with code 1008 before any ears, mouth or brain is built. The token is keyed and not kept in a table so the probe, which holds the same auth token, mints its own for `make probe` (DR-011; the deployment plan's probe call against the container), and so a second task could check one the first minted. With no auth token, `/media` fails closed as `/voice` does, unless `ALLOW_UNSIGNED_WEBHOOKS=1` (local only) (`candidate_line/telephony/app.py`, `candidate_line/probe/session.py`, `tests/test_webhook.py`).
- **The channel.** In the deployment, hand-offs go to SNS email: one topic, the coordinator's addresses subscribed to it, the subject "Candidate Line hand-off" (`SnsPoster` in `candidate_line/escalation.py`, `SNS_TOPIC_ARN`). The container's task role holds `sns:Publish` on that one topic and nothing else, so there is no webhook or key to store, and the role cannot send to anyone the topic does not already list. The ARN holds the account id, so it lives only in the environment, it is never logged, and a failed publish is recorded by its error code alone. SNS is used when the topic is set, Slack when its webhook is, the log poster otherwise; both set means SNS. Slack is not needed for the deployment.
- **The greeting** is now "ACME's automated candidate line. This is Gus. How can I help?", the default proposed under Next, which closes that item: the caller hears that the line is automated in the first sentence, before the human name, as KICKOFF.md section 1 and the customer page say. It is a spec [default] (section 5, Never 3) for James to change. The guard passes it, both forms of the length line and the closed line.
